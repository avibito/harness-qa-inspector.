# Harness QA Inspector — שחזור מצב והעברה (v11)

מסמך זה נכתב משחזור הקוד הקיים בריפו (ללא גישה להתכתבות המקורית ב־ChatGPT).
כל מה שמסומן **[השערה]** הוסק מהקוד ודורש אישור.

## 1. מטרת המערכת
לבדוק האם בדיקת כבילה שבוצעה במכשיר בדיקה חשמלי (ATP + תוצאות) **מכסה במלואה**
את מה שמחייבים השרטוט החשמלי והשרטוט המכני — ולהצביע במפורש על
מקטעים, פינים וזוגות רשתות **שלא נבדקו כלל** או שנבדקו בצורה שאינה מספיקה.

עיקרון־על שנשמר בכל הגרסאות: **המערכת לעולם אינה מאשרת שחרור.**
היא מסווגת ראיות ומפנה לסקירה הנדסית.

## 3. מנוע v10.x — מה נבנה (שחזור מ־v10.6)
**קלט:** שלושה JSON
- שרטוט: `edges[] {id,a,b,kind: wire|shield|resistor|diode, net, ohms?, forward?}` + `revision`, `approved_source`, `source_id`
- ATP: `tests[] {id,a,b,type: continuity|resistance|diode, purpose: segment|end_to_end, min?, max?, direction?, duplicate_reason?}`
- תוצאות: `measurements[] {test_id,value,unit,status?,evidence_ref}`

**לוגיקה:**
1. התאמת מהדורות שרטוט↔ATP↔תוצאות, ומקורות לא מאושרים.
2. בדיקות ATP על נקודות שלא קיימות בשרטוט (`ORPHAN_ATP`), כפילויות עם/בלי הצדקה, בדיקה ללא תוצאה.
3. לכל בדיקה שאינה על מקטע ישיר — מציאת מסלול BFS בגרף; המקטעים במסלול מקבלים "כיסוי עקיף" בתנאים
   (רציפות רק דרך wire/shield, התנגדות לא דרך דיודה, דיודה רק עם כיוון).
4. בדיקת רכיבים (נגד/דיודה) במסלול: סוג בדיקה, כיוון, גבולות, ערך מספרי, יחידה, ראיה → `BLOCKED` או `MEASUREMENT_CONSISTENT_REVIEW`.
5. חריגה מגבולות גם כשהסטטוס רשום PASS (`OUT_OF_LIMIT`).
6. **מטריצת כיסוי לפי מקטע:** `DIRECT_EVIDENCE` / `INDIRECT_COVERAGE` / `ENGINEERING_REVIEW` / `COVERAGE_GAP`.
7. v10.1–10.6: ניהול ממצאים (מזהי F‑xxxx יציבים לפי תצורה), סטטוסים OPEN→IN_PROGRESS→PENDING_VERIFICATION→CLOSED_VERIFIED,
   שער סגירה מחמיר (ביקורת בסיס + ביקורת חוזרת + היעלמות חד־משמעית + מבנה ללא שינוי + פעולה/ראיה/מאמת),
   שמירה ב־localStorage, ייבוא/ייצוא תיק, השוואת בסיס↔חוזרת, שמירת מקורות אחרי רענון.

**החלטות מהותיות שנשמרות:** כיסוי עקיף ≠ הוכחה; היעלמות ממצא ≠ סגירה; שינוי תצורה = תיק חדש; אין אישור שחרור.

## 4. פערים שזוהו ב־v10.6 (ותוקנו ב־v11)
1. **מסלול יחיד:** BFS מחזיר מסלול אחד. כשיש מסלולים מקבילים, מקטע במסלול שנבחר מקבל "כיסוי עקיף" אף שהמדידה הייתה עוברת גם בלעדיו.
   → v11: מקטע מקבל כיסוי עקיף רק אם הוא **הכרחי** לחיבור (הסרתו מנתקת את נקודות הבדיקה).
2. **אין כיסוי ברמת פין/נקודה** — רק ברמת מקטע. → v11: רשימת נקודות שלא נגעה בהן אף בדיקה.
3. **אין בדיקות בידוד/קצר בין רשתות.** → v11: סוג בדיקה `isolation`, ומטריצת זוגות רשתות שלא נבדקו.
4. **השרטוט המכני לא בשימוש.** → v11: רשימת מחברים ופינים מהשרטוט המכני; פינים שאינם בחשמלי (רזרבה) ופינים בחשמלי שאינם במכני.
5. תוצאות ללא בדיקת ATP, תוצאה כפולה לאותה בדיקה (Map שמר בשקט את האחרונה), סטטוס FAIL ללא ערך — לא סומנו. → v11 מסמן.
6. רציפות ללא גבול עליון מתקבלת תמיד. → v11: גבול ברירת מחדל ברמת ATP (`defaults.continuity_max`), ואם חסר — ממצא סקירה.
7. מנוע ו־UI באותו קובץ — לא ניתן לבדיקה אוטומטית. → v11: מנוע נפרד + בדיקות Node.
8. קלט JSON בלבד. → v11: גם CSV (פורמט קרוב לייצוא ממכשירי בדיקה).

## 5. מבנה v11
```
v11/
  engine.js        מנוע טהור (ללא DOM) כולל קריאת CSV — דפדפן ו־Node
  index.html       ממשק (RTL, מותאם לנייד), טוען את engine.js
  build.mjs        בונה קובץ יחיד עצמאי: dist/harness_qa_v11_standalone.html
  samples/         נתוני הדגמה סינתטיים (demo.json + אותם נתונים ב־CSV)
```

הרצת בדיקות: `node v11/tests/engine.test.mjs`
הרצת הממשק: `node v11/build.mjs` ואז לפתוח את `v11/dist/harness_qa_v11_standalone.html` (עובד גם כקובץ מקומי, גם בנייד).

## 6. מה עדיין פתוח
- **[השערה]** פורמט הייצוא של מכשיר הבדיקה בפועל (Cirris / DIT‑MCO / אחר) — לא ידוע. נדרש קובץ אמיתי (מוסווה) כדי לבנות מתאם.
- העברת ניהול הממצאים ושער הסגירה של v10.6 לממשק v11 (המנוע כבר מחזיר מזהי ממצא יציבים ו־`compareAudits`).
- חילוץ נטליסט אוטומטי משרטוט (PDF/DXF) — לא קיים; כיום הנטליסט מוזן ידנית/CSV.
- מקרה בדיקה אמיתי עם תוצאה ידועה לאימות.

## 7. הכרעה (verdict) ב־v11
- `INCOMPLETE` — יש מקטע ללא ראיה, פין שלא נבדק, בדיקה ללא תוצאה או זוג רשתות ללא בידוד.
- `BLOCKED` — הכיסוי שלם אך יש חסמים (חריגה, FAIL, אי־התאמת מהדורות, בדיקת רכיב שגויה).
- `COMPLETE_PENDING_ENGINEERING_REVIEW` — כיסוי שלם וללא חסמים. **עדיין לא אישור.**
